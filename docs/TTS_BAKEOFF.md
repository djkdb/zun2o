# TTS 비교 테스트 (2026-11-08): VoxCPM2 vs Qwen3-TTS vs Chatterbox Multilingual vs Ming-3.0-tts

목적: "12%"의 한국어 대사를 어느 오픈 가중치 모델이 가장 감정적으로 읽는지 비교했습니다. 게임에 들어간 목소리(`voice-refs/*.wav`)를 그대로 유지하는 것이 조건입니다.
환경: 이 컨테이너, CPU 4코어, RAM 15 GB, GPU 없음. 모델마다 venv를 따로 만들었고, 모델은 한 번에 하나씩 돌렸습니다(`torch.set_num_threads(4)`).

> **중요: 저는 귀로 감정을 판단할 수 없습니다.** 아래의 "감정" 관련 수치는 모두 측정 가능한 대리 지표입니다. 말 속도, 피치 변화, 유성음 비율, 스펙트럼 평탄도, 음량을 썼습니다. 이 수치는 "기준 목소리에서 얼마나 벗어났는가"를 보여 줄 뿐이고, "연기가 좋은가"를 보여 주지는 않습니다. 최종 판단은 `qa-output/tts-bakeoff.mp3`를 직접 듣고 내려 주세요.

## 결과물

- **비교 MP3**: `qa-output/tts-bakeoff.mp3` (2분 25초). 대사 6개를 차례로 담았고, 대사마다 아래 순서로 재생됩니다. 모델 사이 1초, 대사 사이 2초 무음이 들어갑니다.
  1. **VoxCPM2** (현재 게임 파이프라인과 같은 설정)
  2. **Qwen3**: 1.7B-Base, 기준 클립으로 복제
  3. **Chatterbox** Multilingual
  4. **Ming**-3.0-tts-0.5B (FREEFORM 지시문 + 기준 클립)
  5. (참고) **Qwen3-VoiceDesign**: 설명문으로 만든 목소리입니다. 게임 목소리와 다른 사람이라 맨 뒤에 붙였습니다.

  비교가 공정하도록 MP3 안의 클립만 -20 LUFS로 음량을 맞췄습니다. 개별 WAV는 원본 그대로입니다.
- **개별 파일**: `qa-output/tts-bakeoff/<모델>-<대사>.wav`(채택 테이크), `<모델>-<대사>-t1.wav`, `-t2.wav`(두 테이크 모두).
  - 모델 이름: `voxcpm2`, `qwen3`, `chatterbox`, `ming`, `qwen3design`, `ming-emotion`(Ming의 감정 프리셋 모드, MP3에는 없음).
  - 대사 ID: `1-entity-a`, `2-entity-b`, `3-male`, `4-female`, `5-mother`, `6-soyeon`.
  - 채택 기준: STT 문자 오류율(CER)이 가장 낮은 테이크, 같으면 1번 테이크. 대부분 1번 테이크가 채택됐습니다.

## 감정 대리 지표 (두 테이크 평균, 역할 기준 클립 대비)

각 칸은 `말 속도 변화 / F0 표준편차 배율 / 유성음 비율 / 스펙트럼 평탄도` 순서입니다.
- 말 속도 변화는 소리 나는 구간의 음절/초를 기준 클립과 비교한 값이고, 음수면 더 느립니다.
- F0 표준편차 배율은 반음 단위 피치 변화를 기준 클립과 비교한 값이고, 1보다 크면 억양 변화가 더 큽니다.
- 진짜 속삭임이라면 유성음 비율이 크게 내려가고(0.5 미만) 평탄도가 올라가야 합니다.

수치로 보이는 경향:
- **"빠르게"를 지킨 모델이 없습니다.** 3-male의 말 속도는 기준 클립(6.6음절/초)과 비슷하거나 더 느렸습니다(+6% ~ -36%).
- **진짜 속삭임에 가까운 결과도 거의 없습니다.** 유성음 비율은 대부분 0.7–1.0이었습니다. 0.5 근처로 내려간 경우는 Chatterbox 2-entity-b(0.41/0.56)와 소연(0.53/0.51), VoxCPM2 소연 2번 테이크(0.47)뿐입니다. 서미령 대사의 음량은 모든 모델에서 기준 클립과 같은 -32 dB 근처라, 조용함이 기준 클립에서 그대로 따라온 것으로 보입니다.
- **기준에서 가장 크게 벗어난 모델은 Chatterbox입니다.** 평균 F0σ가 6.7반음, 범위가 21반음으로 가장 컸습니다(다른 모델 3–4.6반음). 엄마와 소연 대사는 40% 넘게 느려지고 쉼이 길어졌습니다. 그 대신 "속삭임"이어야 할 채원 대사가 기준보다 약 5 dB 크게 나오고 클리핑까지 생겼습니다(아래 참고). 감정의 종류는 고를 수 없고 세기만 올라간다는 뜻입니다.
- **가장 덜 벗어난 모델은 Qwen3 Base와 Ming입니다.** 말 속도는 대부분 ±10% 안이었습니다. 다만 Ming은 서미령 대사를 20–28% 늦췄습니다. 음색은 가장 잘 유지했지만 연기의 폭이 좁을 가능성이 큽니다.
- **VoxCPM2는 지시문을 따르는 흔적이 보입니다.** 서미령 대사가 28–41% 느려졌습니다. 그러나 채원 대사의 화자 유사도가 0.37–0.44로 떨어져, 지시문이 음색까지 바꾼 것으로 보입니다. 소연 1번 테이크는 기준보다 약 9 dB 크고 피크가 0.996이었습니다.

## 모델별 상세

### 1. VoxCPM2 (기준선)
- **라이선스와 한국어**: Apache-2.0이고, 모델 카드 언어 목록에 `ko`가 있습니다.
- **감정 제어**: 게임의 `scripts/voxcpm.py`와 똑같이 `(whispering, slowly, cold and flat)들려요?` 형태로 넣었습니다. 기준 클립은 대본 없이 넣었고, `cfg_value=2.0`, `inference_timesteps=10`입니다. 엄마 대사는 "warm, crying, pleading"입니다.
- **설치**: `uv pip install voxcpm torch torchaudio`(CPU wheel)로 21초 만에 끝났습니다(voxcpm 2.0.3, torch 2.15 CPU). 모델은 4.7 GB이고 로딩에 27초 걸렸습니다. 추가 조치는 필요 없었습니다.
- **속도**: CPU 18.1초/오디오초, 벽시계 5.5배.
- **STT**: CER 평균 0.016. 2-entity-b의 1번 테이크 앞에 "음..."이 붙어 들렸습니다(말줄임표가 소리로 남은 것). 소연 2번 테이크는 "엄마, **아** 두 시 전에는? 와"로 들렸습니다.
- **감지된 문제**: 소연 1번 테이크가 피크 0.996으로 클리핑 직전이었습니다(2샘플). 채원 대사는 음색이 변했습니다(화자 유사도 0.37–0.44). 잘림이나 다른 언어로 읽은 경우는 없었습니다.

### 2. Qwen3-TTS (Qwen/Qwen3-TTS-12Hz-1.7B-Base, 복제)
- **라이선스와 한국어**: Apache-2.0이고, 공식 10개 언어에 한국어가 들어 있습니다.
- **감정 제어**: Base 모델의 `generate_voice_clone`에는 지시문(instruct) 인자가 없습니다. 지시문은 VoiceDesign과 CustomVoice 모델만 받습니다. 그래서 기준 클립과 대본을 주는 ICL 복제만 했고, 감정은 대사 문장 자체와 문장 부호에만 맡겼습니다. 이 점에서 다른 모델보다 불리한 조건이었습니다.
- **설치**: `qwen-tts` pip 패키지(transformers 4.57.3)로 22초 만에 끝났습니다. 모델은 4.3 GB이고 float32, sdpa로 돌렸습니다. "SoX not found"와 "flash-attn not installed" 경고가 나오지만 무시해도 됩니다. 1.7B가 충분히 빨라서 0.6B는 받지 않았습니다.
- **속도**: CPU 21.7초/오디오초, 벽시계 6.3배.
- **STT**: **12/12 테이크 모두 CER 0**. 발음은 가장 안정적이었습니다.
- **감지된 문제**: 앞쪽 무음이 평균 0.23초로 조금 길었습니다. 클리핑, 잘림, 폭주는 없었습니다. "들려요?"가 0.6–0.7초로 매우 짧아, "천천히"가 반영되지 않은 것으로 보입니다.

### 2b. Qwen3-TTS VoiceDesign (참고)
- **감정 제어**: 대사마다 목소리 설명과 연기 지시를 함께 넣었습니다. 예: "A Korean woman in her early forties … Crying and desperately pleading, voice breaking with sobs." 복제가 안 되므로 **게임 목소리와 다른 사람**이 나옵니다(화자 유사도 0.38).
- **결과**: 지시를 가장 강하게 따른 것은 이 모델입니다. 모든 대사가 28–41% 느려졌고 유성음 비율도 낮아졌습니다. 다만 "빠르게"여야 할 3-male까지 느려졌습니다.
- **문제**: 채원 1번 테이크가 **폭주**했습니다. 13.8초 동안 대사를 반복했고, 중간에 "가만 자생 하나나 곤만잠이가" 같은 엉뚱한 말이 섞였습니다. 그 밖에도 문제가 있었습니다.
  - 3-male 1번 테이크에서 "그 폰 꺼요"가 "급혼 거요"로 들렸습니다.
  - 소연 2번 테이크에서 "전에는 와"가 "전에 나와"로 들렸습니다.
  - 끝 무음이 평균 0.6초, 최대 1.26초였습니다.
- 게임 목소리를 유지해야 하므로 이대로는 쓸 수 없습니다.

### 3. Chatterbox Multilingual (ResembleAI/chatterbox, `t3_mtl23ls_v2`)
- **라이선스와 한국어**: MIT이고, 23개 언어에 `ko`가 있습니다. 한국어 입력은 자모로 분해해서 처리합니다.
  - **출력에는 Perth 신경망 워터마크가 들어갑니다.** 들리지는 않는다고 되어 있지만, 게임 에셋에 넣을 때는 알고 있어야 합니다.

### 4. Ming-3.0-tts-0.5B (inclusionAI)
- **라이선스와 한국어**: MIT입니다. 모델 카드와 GitHub LICENSE 둘 다 확인했습니다. 7개 언어에 한국어(`language_id="ko"`)가 있고, MiniMax 다국어 테스트셋 한국어 결과도 카드에 실려 있습니다.
- **감정 제어**: 두 가지 방식을 다 돌렸습니다.
  - (a) `task="FREEFORM"`: 자유 지시문 + 기준 클립 + 대본 + 화자 임베딩. MP3에는 이 방식이 들어갔습니다.
  - (b) `task="EMOTION"`: 7종 감정 프리셋 중 하나를 고릅니다. 서미령은 中性, 도현과 채원은 恐惧, 엄마와 소연은 悲伤을 썼습니다. 결과는 `ming-emotion-*` 파일에 있습니다.
  - 그 밖에 `[Breathing]`, `[Sigh]` 같은 인라인 태그도 지원하지만, 이번에는 쓰지 않았습니다.
- **설치**: pip 패키지가 없어서 GitHub 저장소를 받아 그 코드를 경로로 불러와야 합니다. requirements는 torch 2.6, transformers 4.46.3, diffusers 0.33, x_transformers 2.9.2입니다. 모델은 2.8 GB입니다.
  - 공식 테스트는 H800/H20 GPU에서만 했다고 되어 있습니다.
  - **CPU에서는 그대로 돌아가지 않았습니다.** 코드가 `torch.autocast(device_type='cuda')`만 쓰는데, CPU에서는 이것이 작동하지 않아 Float와 BFloat16이 충돌합니다.
  - `model.generate`만 CPU bf16 autocast로 감싸서 해결했습니다. 화자 임베딩(onnx)까지 감싸면 bf16을 받지 못해 오류가 납니다.
  - 텍스트 정규화(pynini)는 끄고 돌렸습니다. 한국어는 원래 정규화를 거치지 않습니다.
- **속도**: CPU 14.9초/오디오초, 벽시계 4.4배(감정 프리셋 모드는 4.1배).
- **STT**: FREEFORM CER 0.028, 프리셋 0.042.
  - **"…써요"가 4테이크 모두 "어서요", "하우소요", "어, 서요"로 들렸습니다.** 말줄임표가 "어" 소리로 바뀌는 문제가 일관되게 나타납니다.
  - 프리셋 1번 테이크는 "두 시에"가 "도시에"로 들렸습니다.
- **감지된 문제**: 클리핑은 없었습니다. 앞뒤 무음은 약 0.2초씩입니다. 엄마와 소연 대사의 속도가 기준과 거의 같아(±6%), "천천히"나 "울면서"가 속도에는 거의 나타나지 않았습니다. 화자 유사도는 가장 높았습니다(0.77).
